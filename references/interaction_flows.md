# 交互流程手册（interaction_flows.md）

> 本文件供 LLM 在信息采集与卡片渲染阶段加载。包含：芯片文案库、完整对话流、卡片模板、异常话术。

## 1. 选择题芯片文案库

### 1.1 情绪芯片（6 选 1，来自 emotion_palette.json）

| mood_key | 芯片文案 |
|---|---|
| energized | 元气满满，状态在线 |
| cozy | 平静惬意，想舒服一点 |
| celebrate | 达成小事，值得庆祝 |
| steady | 有点疲惫，想吃点熟悉稳妥的 |
| share | 想和朋友分享快乐 |
| explore | 想尝点新鲜花样 |

### 1.2 训练芯片（4 选 1）

`力量日` / `有氧日` / `休息日` / `今天没关注`（映射：力量/有氧/休息日/休息日）

### 1.3 档案芯片（仅首次）

- 过敏原（多选）：`无` / `麸质` / `乳制品` / `鸡蛋` / `鱼类` / `海鲜（虾蟹）` / `大豆` / `坚果花生`
- 忌口：`无` / `不辣` / `不要牛肉` / `不喝咖啡因` /（自由输入）
- 健身目标：`减脂` / `增肌` / `保持` / `不设目标`

### 1.4 取餐方式芯片

`到店自取` / `得来速` / `麦乐送外送` / `预约点餐`（团餐模式自动锁定外送链路）

## 2. 完整对话流

### 2.1 个人餐主流程

```
用户：今天吃什么麦麦
  ↓
[后台] now-time-info → 时段
[后台] profile_manager.py get
  ├─ exists:false → 档案三连问（每题一次芯片）→ init
  └─ exists:true → 继续
  ↓
情绪芯片 → 训练芯片（两题可合并成一条消息的两个问题，但逐题确认更稳）
  ↓
[后台] 营养缓存检查 → （过期则 list-nutrition-foods → parse_nutrition.py）
[后台] recommend_engine.py --mood ... --training ... --goal ... --period ...
  ↓
渲染推荐卡片（§3 模板）+ 引导语：
  "以上是今天的 3 款搭配，回复 A/B/C 选择，或说'换一批'重新调色"
  ↓
【确认①】用户选定
  ├─ "换一批" → 引擎已返回 9 个候选，直接换下一批渲染；用完则带 --exclude "已展示名" 重跑（保证不重复）
  │   └─ --exclude 后仍无新候选 → 引导改约束："换个心情试试？"或"换个时段看看？"（不空转）
  └─ 选定 → 进入门店环节
  ↓
query-nearby-stores（取前 3 家，带距离）→ 用户选店
  ↓
方式芯片 → 按 §1.4 分支：
  ├─ 到店自取 → query-meals(beType=1)
  ├─ 得来速 → 用所选店的 beCode，query-meals(beType=5, beCode=...)
  ├─ 麦乐送 → delivery-query-stores → delivery-query-addresses（空则 delivery-create-address）→ query-meals(beType=2)
  └─ 预约 → 先问预约时间（日期+时段芯片）→ 按所属场景走 + reservationDate
  ↓
【套餐复核】对所选套餐：用 query-meals 按套餐名+menu_code_hint 定位真实商品
  ├─ 缺失或价差 >15% → 按 §4「套餐未上架/套餐价偏差」话术处理
  └─ 正常 → 进入下单准备
【映射】套餐：名称命中即取其 code（roundList 结构见 query-meal-detail）；组合：bridge_name.py match 逐品映射
用户确认了 swap_options 换子项 → query-meal-detail 取 roundList choice code（如 3050 可乐中杯）
  ↓
calculate-price（items 带 productCode/quantity）
  → 价格 ÷100 展示；记下 takeWayList 供自取/得来速选 takeWayCode
  → 顺手调 available-coupons（只读）提示可用券
  ↓
【确认②】订单复述表格 + "回复『确认下单』我才会提交订单"
  ↓
create-order → 支付引导 → "支付完成后请回复'支付完成'或'支付失败'"
  ↓
【确认③】query-order 反馈状态；用户说"订单状态"随时查
```

### 2.2 团餐分支

```
触发：团队/聚餐/团建/组里/多人点麦当劳
  ↓
采集（2 题）：聚餐目的芯片（项目庆功/部门团建/朋友聚会/家庭聚餐）
           + 人数 + 人均预算（默认 30，提示官方 5 档规则）
  ↓
[后台] recommend_engine.py --mode party --purpose ... --headcount ... --budget-per-head ...
  → 输出按档位的组合（含 ×人数 数量）
  ↓
口头确认团队忌口（团餐不套个人档案过滤）
  ↓
query-meal-assistance → gmServiceCode（失败则告知该店暂不支持团餐并换店）
query-meals(beType=6, beCode) → calculate-price
  ↓
【确认②】复述表格（数量列 ×人数）+ 确认下单
  ↓
create-order(beType=6, orderType=2, addressId, gmServiceCode, beCode)
  → 支付引导与状态跟踪同主流程
```

## 3. 推荐卡片模板（v2 套餐优先）

### 3.1 完整模板

```
麦麦心情调色盘 · 今日配方
今日情绪色：焦糖棕 × 薯条金（达成小事，值得庆祝）
今日营养带：450–800 kcal · 蛋白 ≥35g（减脂·力量日·午餐）
──────────────────────
A 大堡口福三件套（含：鸡排堡+中薯条+可乐中杯）
   ¥21.9 · 单点合计 ¥47.5 · 省 ¥25.6
   680 kcal（换小杯玉米杯后）· 蛋白 24g
   推荐理由：小成就值得大口吃肉，套餐价直接省一半
B 龙焰鸡腿堡三件套（含：龙焰堡+中薯条+可乐中杯）
   ¥25.9 · 单点合计 ¥48 · 省 ¥22.1
   685 kcal（换小杯玉米杯后）· 蛋白 28g
   推荐理由：韩式新品配招牌仪式感，省 ¥22 尝个鲜
C 精选单人餐三件套（含：板烧鸡腿堡+中薯条+可乐中杯）
   ¥33.5 · 单点合计 ¥46.5 · 省 ¥13.0
   591 kcal（换小杯玉米杯后）· 蛋白 27g
   推荐理由：稳妥的经典三件套，热量轻一点
──────────────────────
回复 A/B/C 选择 · 说"换一批"重新调色
＊套餐/单品价格与营养为参考值，以门店实时价为准；营养与过敏原信息仅供参考，不构成营养或医疗建议
```

### 3.2 渲染规则

- 第一行固定「麦麦心情调色盘 · 今日配方」；情绪色与营养带来自引擎 `emotion_palette` / `nutrition_band`
- **套餐卡（kind=set_meal）**：显示「名称（含：构成）」→「套餐价 · 单点合计 · 省 ¥X」→「热量（换子项后）· 蛋白」→ 推荐理由
  - `savings` 是核心利益点，必须展示
  - `swap_options` 非空时热量标注「换 XX 后 NNN kcal」
  - `nutrition_estimated: true` 时热量后加 `*`，脚注说明「*含估算值」
- **组合卡（kind=combo）**：维持 v1 样式（items 用 + 连接），`over_budget: true` 时标注「超营养带」并附 downsize_options
- `set_meal_status.degrade_note` 非空时，卡片头部加一行提示：「当前时段套餐少，为你补充单品组合推荐」
- 免责脚注每张卡片必须带（含套餐价格以门店实时价为准的提示）
- LLM 写推荐理由时遵循 compliance_wording.md 替代表达

### 3.3 套餐与组合混合展示

- 前 3 推荐以套餐为主（引擎已按套餐优先排序）；若前三为「2 套餐 + 1 组合」属正常（组合在情绪/营养上更强时入围）
- 用户选定套餐后，选店环节按 SKILL.md「选店后套餐复核」校验真实菜单与价格

## 4. 异常话术

| 场景 | 话术 |
|---|---|
| 401 | mcd-mcp 连接器 Token 可能无效或过期，请在 WorkBuddy 连接器设置中检查后重试 |
| 429 | 麦麦服务器刚刚有点忙，等一分钟再试一次，还不行的话稍后再来 |
| 引擎无候选 | 今天先不管营养带，看看情绪色搭配（改 --goal 无 重跑） |
| 桥接无匹配 | 这家店的菜单叫法不太一样，我找到最接近的是 XX，可以吗？（LLM 从 query-meals 结果近邻选择并向用户确认） |
| 套餐未上架 | 你选的套餐这家店暂时没有，我换个同类套餐给你（或回到推荐换一批），复述后重新确认 |
| 套餐价偏差 | 这家店该套餐实价 ¥XX（与参考价有差异），价格以门店为准，确认继续吗？ |
| 降级提示 | 当前时段套餐少/热量限制下套餐不合适，为你补充了单品组合推荐 |
| 用户拒绝答情绪题 | 好的，按「平静惬意」帮你搭（默认 cozy） |
| 支付失败 | 先 query-order 看状态：仍在支付窗口内 →「订单还挂着，可以重新扫码支付」；已超 15 分钟自动取消 →「这单已超时自动取消，需要的话我帮你重新下单」（重新走确认②） |
